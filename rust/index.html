Fundamentals

What is &[u8]?

A borrowed reference to a contiguous sequence of bytes
PartMeaning
[u8]Slice of unsigned 8-bit integers — unsized, can't exist alone
&Borrowed reference — no ownership, no copy

Fat pointer under the hood

&[u8] is two machine words: a pointer to the first byte, and the length.

In networking code, &[u8] is the universal currency — every packet parser takes a byte slice because it avoids copying raw packet data.
Fundamentals

Creating &[u8]

Three common sources of byte slices
// From a Vec
let vec: Vec<u8> = vec![0x08, 0x00, 0x4a, 0x5c];
let slice: &[u8] = &vec;

// From a fixed-size array
let array: [u8; 4] = [0x08, 0x00, 0x4a, 0x5c];
let slice: &[u8] = &array;

// Sub-slice (zero-copy window into existing data)
let sub: &[u8] = &vec[1..3];  // [0x00, 0x4a]
All three produce the same type: a pointer + length. No data is copied — each slice borrows from the original allocation.
Syntax

The [..] full-range slice

Converting a fixed-size array into a dynamically-sized slice
let mut packet = [0u8; 14];           // type: [u8; 14]

let header = MutableEthernetPacket::new(
    &mut packet[..]                    // type: &mut [u8]
).unwrap();

Step by step

ExpressionTypeWhat happens
packet[u8; 14]Fixed-size array on the stack
packet[..][u8]Index with RangeFull → unsized slice
&mut packet[..]&mut [u8]Mutable borrow of the whole array as a slice

All range variants

&packet[..]       // all 14 bytes       [0..14]
&packet[..6]      // first 6 bytes      destination MAC
&packet[6..]      // bytes 6 onward     source MAC + ethertype
&packet[12..14]   // 2 bytes             ethertype field
&mut packet would also work here — Rust auto-derefs &mut [u8; 14] into &mut [u8]. But [..] makes the intent explicit.

Implementation

Decoding ICMP with pnet

Ethernet → IPv4 → ICMP parse chain
use pnet::packet::ethernet::{EthernetPacket, EtherTypes};
use pnet::packet::ipv4::Ipv4Packet;
use pnet::packet::icmp::{IcmpPacket, IcmpTypes};
use pnet::packet::Packet;

fn decode_icmp(epb_data: &[u8]) {
    let eth = EthernetPacket::new(epb_data).unwrap();
    if eth.get_ethertype() != EtherTypes::Ipv4 { return; }

    let ipv4 = Ipv4Packet::new(eth.payload()).unwrap();
    if ipv4.get_next_level_protocol().0 != 1 { return; }

    let icmp = IcmpPacket::new(ipv4.payload()).unwrap();

    match icmp.get_icmp_type() {
        IcmpTypes::EchoRequest => println!("Ping"),
        IcmpTypes::EchoReply   => println!("Pong"),
        _ => {}
    }
}

Each ::new() takes &[u8] and returns a zero-copy wrapper that reads fields from the underlying bytes by offset.

Implementation

Manual decode — no dependencies

Parsing by raw byte offsets
fn decode_icmp_manual(epb_data: &[u8]) {
    // Ethernet: 14 bytes
    let ethertype = u16::from_be_bytes([epb_data[12], epb_data[13]]);
    if ethertype != 0x0800 { return; }

    // IPv4: variable header length
    let ip = &epb_data[14..];
    let ihl = ((ip[0] & 0x0F) as usize) * 4;
    if ip[9] != 1 { return; }   // protocol != ICMP

    // ICMP: starts after IP header
    let icmp = &ip[ihl..];
    let icmp_type = icmp[0];
    let icmp_code = icmp[1];
    let checksum  = u16::from_be_bytes([icmp[2], icmp[3]]);

    // Echo request (8) or reply (0): ID + sequence follow
    if icmp_type == 8 || icmp_type == 0 {
        let id  = u16::from_be_bytes([icmp[4], icmp[5]]);
        let seq = u16::from_be_bytes([icmp[6], icmp[7]]);
    }
}
This is essentially what pnet does internally — every .get_*() is an offset read into the borrowed &[u8].
Architecture

The decode stack

Each layer slices into the next — no allocation, no copy
Every layer calls .payload() or uses a range slice — the original &[u8] is never copied. This is why Rust is a natural fit for packet processing.

Takeaways

  • &[u8] is a fat pointer: address + length
  • [..] coerces arrays into slices
  • Sub-slicing is zero-copy — just pointer arithmetic
  • Packet parsing chains slices layer by layer
  • pnet wraps the offset math; manual decode does the same thing
  • u16::from_be_bytes() handles network byte order

Parsing (read a packet)

let eth = EthernetPacket::new(raw_bytes).unwrap();

eth.get_destination()   // [u8; 6] — dst MAC
eth.get_source()        // [u8; 6] — src MAC
eth.get_ethertype()     // EtherType
eth.payload()           // &[u8] — everything after the 14-byte header

Building (write a packet)

let mut buf = [0u8; 14];
let mut eth = MutableEthernetPacket::new(&mut buf[..]).unwrap();

eth.set_destination(MacAddr::new(0xff,0xff,0xff,0xff,0xff,0xff));
eth.set_source(MacAddr::new(0x00,0x1a,0x2b,0x3c,0x4d,0x5e));

This pattern repeats across pnet: ipv4 has Ipv4Packet / MutableIpv4Packet, icmp has IcmpPacket / MutableIcmpPacket, etc. Learn one, you know them all.
Ownership

Cow<'a, [u8]>

Clone on Write — borrow when you can, own when you must

The enum

pub enum Cow<'a, B: ?Sized + ToOwned> {
    Borrowed(&'a B),                     // just a reference
    Owned(<B as ToOwned>::Owned),      // owned copy
}

For Cow<'a, [u8]>

VariantHoldsCost
Cow::Borrowed(&'a [u8])Reference to someone else's bytesZero-copy
Cow::Owned(Vec<u8>)Its own Vec<u8>Allocated

Reading — free either way

// Cow derefs to &[u8] automatically
let first = block.data[0];
let slice: &[u8] = &block.data;
let eth = EthernetPacket::new(
    &block.data
).unwrap();

Mutating — clones only if borrowed

// .to_mut() clones if Borrowed,
// no-op if already Owned
let bytes = block.data.to_mut();
bytes[0] = 0xff;

// .into_owned() consumes into Vec
let v: Vec<u8> = block.data.into_owned();

Key methods

MethodReturnsClones?
&*cow&[u8]Never
.to_mut()&mut Vec<u8>Only if currently Borrowed
.into_owned()Vec<u8>Only if currently Borrowed
Think of it like a library book: Borrowed = reading the library's copy (free). to_mut() = you need to highlight, so you photocopy first. If you already own it, no photocopy needed.
Deep dive

Lifetimes: 'a

Compile-time proof that references never dangle
// "the returned slice lives at least as long as the input"
fn first_half<'a>(data: &'a [u8]) -> &'a [u8] {
    &data[..data.len() / 2]
}

The problem Rust solves

// C — compiles fine, crashes at runtime (dangling pointer)
char* get_name() {
    char buf[64];
    sprintf(buf, "hello");
    return buf;  // buf is dead after return!
}

Design lineage

YearSystemContribution
2001Cyclone (Cornell)Region-based memory safety for C — @region pointers
2006Rust startedGraydon Hoare at Mozilla, motivated by Firefox memory bugs
2012Rust lifetimesCyclone regions simplified to 'a syntax
Lifetimes exist only at compile time — zero runtime code generated. The ' prefix separates lifetime params from type params: <'a, T>.
Deep dive

[u8] — the unsized slice

A dynamically-sized type that always carries its length
[u8; 14]   // Sized — compiler knows: exactly 14 bytes
[u8]       // Unsized — length only known at runtime

let x: [u8];        // ERROR: can't live on the stack
let x: &[u8];       // OK: fat pointer (ptr + len) = 2 words
let x: Box<[u8]>;   // OK: pointer to heap

The C array problem this fixes

// C — arrays decay to pointers, length is lost
void process(uint8_t* data) {
    data[999] = 0;  // compiles fine, buffer overflow
}

// Rust — &[u8] always carries the length
fn process(data: &[u8]) {
    data[999];  // bounds check — panics safely
}
Rust's [T] is deliberately unsized so it can only exist behind a fat pointer. This makes it impossible to lose the length — the type system enforces it.

Rust's design philosophy

You don't pay for what you don't use

Three approaches to memory safety

LanguageStrategySafetyRuntime cost
CTrust the programmerNoneZero
Java / GoTrust the runtime (GC)FullGC pauses + overhead
RustTrust the compiler (lifetimes)FullZero

Reading Cow<'a, [u8]> right to left

PartMeaningDesign reason
[u8]Sequence of bytesDST — length unknown at compile time
'aLives at least as long as 'aCompiler proves no dangling reference
Cow<...>Either borrowed or ownedClone only when mutation needed
The core insight: if you encode ownership rules into the type system, the compiler proves memory safety at compile time, with zero runtime overhead. Every piece of syntax — 'a, &, [T], Cow — is a building block in that proof system.

Function wantsHowClones?

The rule

// Functions should accept the most
// general type that works.
//
// &[u8] is more general than
// &Vec<u8> or &Cow<[u8]>
//
// because anything holding bytes
// can produce &[u8] via Deref.

fn good(data: &[u8]) {}     // accepts all
fn bad(data: &Vec<u8>) {}   // only Vec
Deref coercion: when a function expects &T and you pass &U where U: Deref<Target = T>, the compiler auto-inserts .deref(). This is why &cow, &vec, and &array all just work.

Making EtherType readable

EtherType(2048) → "IPv4"

Match on pnet constants

let name = match eth.get_ethertype() {
    EtherTypes::Ipv4 => "IPv4",
    EtherTypes::Ipv6 => "IPv6",
    EtherTypes::Arp  => "ARP",
    EtherTypes::Vlan => "VLAN",
    EtherTypes::Lldp => "LLDP",
    other => {
        println!("0x{:04x}", other.0);
        "Unknown"
    }
};

Access the raw u16

let et = eth.get_ethertype();
println!("{}", et.0);        // 2048
println!("0x{:04x}", et.0); // 0x0800

.0 accesses the inner u16 of the EtherType newtype wrapper.
