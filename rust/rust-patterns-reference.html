Pattern kind

Literal patterns

Match against an exact value — numbers, chars, strings, booleans
match code {
    200 => println!("ok"),
    404 => println!("not found"),
    _ => println!("other: {code}"),
}

match letter {
    'a' => println!("first"),
    true => {} // booleans are literal patterns too
}

The value must implement PartialEq at compile time in a comparable way — integers, floats (discouraged for exact-match reasons), chars, strings, and bool all work as literal patterns.

Pattern kind

Identifier patterns

The plain name pattern — binds (or moves) the matched value
let x = 5;                 // x is an identifier pattern

match Some(10) {
    Some(n) => println!("got {n}"),  // n binds the inner i32
    None => {}
}

// with @ to also test a subpattern (see @ bindings slide)
match 7 {
    n @ 1..=9 => println!("digit {n}"),
    _ => {}
}

By default this moves or copies the value into the new binding. Use ref/ref mut to borrow instead (see the ref slide), or match on a reference to get the same effect via default binding modes.

Reference reference/patterns.html#r-patterns.ident  ·  #r-patterns.ident.binding (binding modes)
Pattern kind

Wildcard pattern _

Matches anything, binds nothing — the "I don't care" pattern
match pair {
    (0, _) => println!("first is zero"),
    (_, 0) => println!("second is zero"),
    _ => println!("neither is zero"),
}

let _ = expensive_call();  // run for side effects, discard result
let (a, _, c) = (1, 2, 3); // skip the middle element

Unlike a named binding, _ never triggers "unused variable" warnings and never moves the value out (important when the value has a destructor you don't want to run early — a bare _x also avoids the warning but still binds/drops immediately; _ alone binds nothing at all).

Pattern kind

Rest pattern ..

"And everything else" — for structs, tuples, slices
let arr = [1, 2, 3, 4, 5];
let [first, .., last] = arr;          // first=1, last=5
let [head, tail @ ..] = arr;       // head=1, tail=[2,3,4,5]

struct Point3 { x: i32, y: i32, z: i32 }
let Point3 { x, .. } = p;              // only care about x

match (1, 2, 3, 4) {
    (first, .., last) => println!("{first}..{last}"),
}

.. can appear at most once per pattern (otherwise the match would be ambiguous about how many elements it consumes). Combine with @ (tail @ ..) to bind the rest to a name instead of discarding it.

Pattern kind

Range patterns

a..=b inclusive ranges over chars and numbers
match grade {
    90..=100 => println!("A"),
    80..90   => println!("B"),   // half-open, exclusive end
    _        => println!("C or below"),
}

match c {
    'a'..='z' => println!("lowercase"),
    'A'..='Z' => println!("uppercase"),
    _ => println!("other"),
}

Only types with a defined, contiguous ordering (integers, floats, char) support range patterns. The old ... inclusive syntax is deprecated in favor of ..=.

Pattern kind

Reference patterns & / &mut

Match through a reference by peeling it off in the pattern
let v = vec![1, 2, 3];

for item in &v {                 // item: &i32
    println!("{item}");
}

match v.first() {
    Some(&first) => println!("{first}"),  // &i32 -> i32 by deref pattern
    None => {}
}

let mut n = 5;
if let &mut inner = &mut n { inner += 1; }

Not to be confused with ref (which creates a reference during binding) — &pattern instead expects a reference and matches what's behind it. Since Rust 2018's "match ergonomics," you often don't need this explicitly — the compiler infers it.

Pattern kind

Struct patterns

Destructure named fields, in any order
struct Point { x: i32, y: i32 }
let p = Point { x: 1, y: 2 };

let Point { x, y } = p;              // field-name shorthand
let Point { x: a, y: b } = p;         // rename while destructuring

match p {
    Point { x: 0, y } => println!("on y-axis at {y}"),
    Point { x, .. } => println!("x={x}"),    // .. ignores y
}

Fields can be matched by literal, sub-pattern, or ignored with ... Field order in the pattern doesn't need to match declaration order — structs are matched by name, not position.

Pattern kind

Tuple struct patterns

Destructure by position — includes enum variants with data
struct Color(u8, u8, u8);
let Color(r, g, b) = Color(255, 0, 0);

// enum variants ARE tuple structs, pattern-wise
enum Shape { Circle(f64), Rect(f64, f64) }

match shape {
    Shape::Circle(radius) => println!("r={radius}"),
    Shape::Rect(w, h) => println!("{w}x{h}"),
}

This is the pattern you've been using all session with Block::EnhancedPacket(epb) and Some(name) — any tuple-like variant or struct destructures positionally with parentheses.

Reference reference/patterns.html#r-patterns.tuple-struct
Pattern kind

Tuple patterns

Destructure plain (unnamed-type) tuples
let (x, y, z) = (1, 2, 3);

let pair = (Some(5), 10);
match pair {
    (Some(n), total) => println!("{n} of {total}"),
    (None, total) => println!("none of {total}"),
}

let one_tuple = (5,);   // trailing comma required for arity 1

The empty tuple pattern () matches the unit type. Arity must match exactly — unlike slices, there's no partial-length tuple pattern without a .. rest.

Reference reference/patterns.html#r-patterns.tuple
Pattern kind

Grouped patterns ( ... )

Parentheses to disambiguate precedence — mostly with | and ..=
match value {
    (1 | 2) => println!("one or two"),   // grouping clarifies scope of |
    _ => {}
}

// combined with @ — group the range being tested
match n {
    x @ (1..=5 | 10..=15) => println!("in range: {x}"),
    _ => {}
}

Rarely needed on its own since a top-level pattern is already unambiguous, but essential once you mix | or ranges inside a larger pattern (e.g. inside an @ binding, as above) where precedence would otherwise be unclear.

Reference reference/patterns.html#r-patterns.paren
Pattern kind

Slice patterns

Match array/slice contents and shape at once
match slice {
    [] => println!("empty"),
    [only] => println!("one: {only}"),
    [first, second] => println!("two: {first}, {second}"),
    [first, .., last] => println!("{first}..{last}"),  // 2+ elements
}

let pkt: &[u8] = &[0x08, 0x00, 1, 2];
if let [0x08, 0x00, rest @ ..] = pkt {
    println!("IPv4 ethertype, {} bytes follow", rest.len());
}

Unlike tuples, slices can match variable length via .. since the length isn't part of the type for &[T] (fixed-size arrays [T; N] can still require exact length when no rest pattern is used).

Pattern kind

Path patterns

Match a unit struct, fieldless enum variant, or associated constant by name
enum Direction { North, South, East, West }

match dir {
    Direction::North => println!("N"),  // fieldless variant, matched by path
    Direction::South => println!("S"),
    _ => println!("other"),
}

const MAX: i32 = 100;
match value {
    MAX => println!("at the cap"),   // const pattern: compares by value
    _ => {}
}

Careful: an UPPER_CASE or path-like name in a pattern is treated as a constant/path to compare against, not a new binding — only a plain lowercase identifier introduces a binding (identifier pattern, slide 2). This is a classic beginner trap.

Pattern kind

Or-patterns |

Match any one of several alternatives in a single arm
match c {
    'a' | 'e' | 'i' | 'o' | 'u' => println!("vowel"),
    _ => println!("consonant"),
}

// works nested inside other patterns too
match msg {
    Message::Quit | Message::Close => println!("stopping"),
    Message::Move { x: 0 | 100, .. } => println!("at an edge"),
    _ => {}
}

All alternatives must bind the same set of names with the same types (you can't have Ok(x) | Err(x) bind x to different types). This is the pattern-level equivalent of stacking multiple match arms with identical bodies.

Reference summary

Refutability & where each kind is legal

Not every pattern kind is allowed in every pattern site
KindRefutable?Typical use
LiteralYesmatch arms
IdentifierNoeverywhere — let, fn params, for
Wildcard _Noeverywhere
Rest ..context-dependentstruct/tuple/slice patterns
RangeYesmatch arms
Reference &depends on inner patternmatching through refs
Struct / tuple struct / tupleNo, if exhaustive over fieldslet, match
Sliceusually Yesmatch, if let
Path / constYesmatch arms
Or |Yesmatch arms, if let
Rule of thumb: let, for, and function/closure parameters require irrefutable patterns — ones that are guaranteed to match. match arms, if let, and while let accept refutable patterns, since "doesn't match" is exactly what the other arm/branch handles.
